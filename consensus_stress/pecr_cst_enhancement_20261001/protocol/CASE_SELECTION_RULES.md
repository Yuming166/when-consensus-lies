# V2 case selection rules (fixed before V2 selection)

Seed: `20260930`; deterministic rank: SHA256(`seed|category|id`). V1 data and cases were already inspected; this is a fixed rule for this V2 descriptive rerun, **not a preregistered or held-out confirmatory analysis**.

1. PECR universe is the existing dev_train construction manifest. Read construction_status and construction_flags from the nested bidirectional object; do not interpret the top-level provenance/status string as a failed construction. Strict-analysis responses are obtained by projecting only ID, source_group, direction, operation, responses, parse_reasons, and status from the existing parsed file. The file also stores labels, so file access is not label blindness; labels, scores, and graph features are not inputs to ranking. Raw ledger responses and actual request edits must corroborate each selected case.
2. Candidate response classes use three numeric values and expected direction d in {-1,+1}: epsilon=max(1e-9,1e-6*max(1,abs(original))). Both oriented differences greater than epsilon -> direction-pass; both absolute differences <= epsilon -> flat; both oriented differences < -epsilon -> opposite; otherwise mixed. These are mechanical/program-conditioned response classes, not human-validated semantic success/failure.
3. Select two examples per PECR response class in order direction-pass, flat, opposite, mixed; prefer an unused true source_group, then fill from the same class if needed. Candidate eligibility requires nested valid_candidate, strict row complete, and unit consistency under the existing strict parser. Do not select by original correctness, HGB risk, performance, appeal, or author preference. All eligible IDs and ranks are saved.
4. Select two PECR construction-failure examples from the entire manifest pool whose nested construction_status is not valid_candidate, using the same hash order. Save specific flags. Missing responses are expected for filtered items; do not fabricate them or call models.
5. CST universe is Round-7 ind_ce items and available Round-6 original records. Recompute per-agent flips from stored decisions, verify against _agent_flip, and use exact denominators. Select one each for all counter/all placebo flip, all counter/no placebo flip, no counter/all placebo flip, and neither, using the same hash order. No correctness labels or risk scores enter ranking. Pair ID is only a paired experimental cluster; it is not an established source group.
6. Verify exact input edits using stored artifacts/cache messages. A hash alone is not an input text. If raw messages or source-group mapping are missing, mark that field missing. Do not infer authorization from local presence. License/redistribution status and human semantic review are separate fields; absent evidence blocks public case confirmation, not internal provenance auditing.
7. Illustrations never estimate overall effects. Empty strata and requested but unverified semantic-validity strata remain visibly unfilled. CST V3 invalidity remains boundary evidence; no validated-test-set claim.
8. No holdout reads, model/API calls, label/score mutation, training, new experiment, git operation, or edits outside this V2 directory.
