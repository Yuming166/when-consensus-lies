# 独立反向构造盲审：审阅者操作说明

## 目的与盲法
本审查只判断表格编辑定位、同一表内财务关系、单位一致性及预期方向是否合理。审阅者不会收到任何模型回答、置信度、正确性标签、AUROC、风险分数或 holdout 样本。题目所示程序操作类别和预期方向属于 program-conditioned 审查输入；请判断它是否与题目及被编辑单元格相符。不要尝试猜模型对错。

## 每题步骤
1. 先对比 original、positive、reverse 三张表，确认指定单元格和 old/positive/reverse 数值是否与表格一致。
2. 查阅问题、表头、年份、货币/比例/数量单位和表内相关总计/分项。判断单元格变化是否要求同步改变相关恒等式中的其他格；若原表不是加总关系，也不要强行假设。
3. 分别判断正向与反向构造的财务关系和单位是否保真。
4. 按给出的 operation type / program direction，判断两个编辑在题目所需运算中的预期输出方向是否合理。程序信息是被审对象的一部分，不是正确性标签。
5. 每一项选 `YES`、`NO`、`UNCERTAIN` 之一；总体选择 `VALID`、`INVALID`、`UNCERTAIN`。不得删除难题、缺信息题或不合意题。

## INVALID / UNCERTAIN 判准
- **INVALID**：编辑位置/值不对应；编辑破坏明确可见的表内恒等式或跨表关系；单位、年份或期间被混淆；正负扰动不是所声明方向；明显违反题目语义或表格约束。记录具体依据。
- **UNCERTAIN**：需要外部知识或原始报告上下文才能判断；表内关系含糊；舍入/符号约定不清；无法判断程序方向或单位。不要把 UNCERTAIN 自动算作 VALID。
- **VALID**：四类检查均有足够材料支持，且 positive 与 reverse 两侧都成立。

## 禁止事项
不得查看或搜索同一题的模型回答、正确答案、标签或风险评分；不得把“模型回答按预期变化”作为财务构造有效性的证据。不要擅自改写包内原始表格。

## 回收与冻结
审阅完成后，将完整 CSV/JSONL 裁决表交给项目负责人；不得删除任何抽中题。负责人先计算文件 SHA-256 并保存原始只读副本，再冻结审阅者身份/日期、裁决文件哈希、缺失项和分歧解决规则。双审时先报告独立裁决一致性，再由第三方按预先规则处理分歧；禁止在看模型表现或标签后改裁决。Codex 可机械汇总和计算一致性，但不代填独立结论。
